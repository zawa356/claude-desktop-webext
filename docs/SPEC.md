# Specification (schema 1)

Both implementations — `bin/webext.ps1` (Windows) and `bin/webext.py` (Linux; also runs on Windows for tests) — follow this document. For the same input, they must write byte-identical `manifest.json` files. `tests/loader.test.mjs` checks this.

## Paths

| | Windows | Linux |
|---|---|---|
| Slot (generated) | `%APPDATA%\Claude\extensions\fmkadmapgofadopljbjfkapdkoienihi` | `$XDG_CONFIG_HOME/Claude/extensions/fmkadmapgofadopljbjfkapdkoienihi` (default `~/.config`) |
| Home | `%LOCALAPPDATA%\ClaudeDesktopWebExt` | `$XDG_DATA_HOME/claude-desktop-webext` (default `~/.local/share`) |
| Store | `<home>\web-extensions\<id>\` | same |
| State | `<home>\state.json` | same |
| Backups | `<home>\backups\<stamp>\...` | same |
| Lock | `<home>\.lock` | same |
| REACT_PROFILE | user registry value `HKCU\Environment` | `~/.config/environment.d/90-claude-desktop-webext.conf` |

## Installation discovery

Windows uses MSIX registrations, running executable paths, classic uninstall registry
InstallLocation/DisplayIcon and standard locations. Registry commands are never executed.
A `claude.exe` is a candidate only if `resources\app.asar` exists next to it; this excludes
other programs with the same name, such as the Claude Code CLI. The running-process count
uses the same test. Of the `app-*` folders of one installation directory, only the newest
usable one (highest version in the folder name) is a candidate. Candidates are deduplicated by executable path (case insensitive). Select the sole
running candidate, otherwise the sole candidate; multiple candidates block changes.
`-ClaudePath` selects an executable or installation directory explicitly. An invalid
explicit path blocks changes. No detected candidate gives a warning for backward
compatibility; this does not verify runtime support. Sandbox discovery uses
`claude-package.json` and `claude-installations.json` and never scans the host.
Linux discovers app.asar in standard directories; multiple candidates block changes.
`--claude-path` accepts an installation directory, executable or app.asar.

App installation location and user-data destination are independent. Keep the existing
slot path. On Windows, either the normal user-data directory or an existing registered
package's virtual user-data directory satisfies the started-once check. With only the
latter, install creates the normal slot path; diagnose creates nothing. Virtual slots
from any discovered package block changes, including uninstall. Explicit installation
selection never bypasses slot ownership, virtual-shadow, environment or schema checks.
Custom user-data paths are not inferred. Linux retains its XDG user-data rules.

## Files

`state.json` (written only by the loader):

```json
{ "schema": 1, "generation": 3, "envSetByUs": true,
  "extensions": { "<id>": { "displayName": "...", "version": "...", "order": 10, "installedAt": "...", "updatedAt": "..." } } }
```

Slot marker `<slot>/.claude-desktop-webext.json`:

```json
{ "schema": 1, "tool": "claude-desktop-webext", "loaderVersion": "0.2.1", "generation": 3, "generatedAt": "...",
  "extensions": [ { "id": "...", "version": "...", "order": 10 } ], "skipped": [ { "id": "...", "reason": "..." } ] }
```

A loader whose schema is lower than the `schema` of `state.json` or of the slot marker must refuse every change. It reports "update this tool".

## Merge

1. Candidates: every directory in the store whose name matches `^[a-z0-9][a-z0-9._-]{0,63}$` and does not start with `.`.
2. Validate each one; invalid ones are skipped and listed in the marker.
   - `manifest_version` is exactly `3`.
   - Top-level keys come only from: `manifest_version, name, short_name, version, version_name, description, author, homepage_url, icons, minimum_chrome_version, browser_specific_settings, content_scripts, permissions`.
   - `name` is a string without `__MSG_`.
   - `permissions` ⊆ `{storage}`.
   - `content_scripts` is non-empty. Each entry uses only keys from `matches, exclude_matches, include_globs, exclude_globs, css, js, run_at, world, all_frames, match_about_blank, match_origin_as_fallback` and has `matches` plus `js` or `css`.
   - `world` ∈ {`MAIN`, `ISOLATED`}; `run_at` ∈ {`document_start`, `document_end`, `document_idle`}.
   - Every `js`/`css` path is relative, uses `/`, contains no `.`/`..`/empty segment, `?`, `#` or drive letter, and names an existing file.
3. Sort the valid extensions by (`order` from state, default 100; then `id` by ordinal comparison).
4. Generated `manifest.json` (key order as listed):
   - `manifest_version`: `3`
   - `name`: `"Claude Desktop WebExt"`
   - `version`: `"1.<generation div 65535>.<generation mod 65535>"`
   - `description`: `"Generated by claude-desktop-webext. Do not edit. Extensions: <ids joined by ', '>"`
   - `permissions`: sorted union (ordinal); omitted when empty
   - `content_scripts`: each extension's entries in source key order, with every `js`/`css` path rewritten to `ext/<id>/<path>`
5. The slot contains `manifest.json`, the marker, and `ext/<id>/` (a full copy of each valid extension folder).

JSON is written with 2-space indentation, `": "` between key and value, LF line endings, UTF-8 without BOM, a trailing newline, and non-ASCII characters left unescaped. Escaped characters: `"` `\` and control characters (`\b \f \n \r \t`, otherwise `\u00XX`).

## Slot ownership

| State | Detection | install | uninstall | rebuild |
|---|---|---|---|---|
| none | slot missing | create | — | nothing to do |
| ours | marker with `tool = claude-desktop-webext` | replace | replace / remove | replace |
| adoptable | contains a file listed in the caller's `adopt.markers`, or its manifest `name` is in `adopt.manifestNames` | move to backups, replace | — | refuse |
| react-devtools | manifest name contains `React Developer Tools` | refuse | refuse | refuse |
| unknown | anything else | refuse | refuse | refuse unless `-TakeOver` / `--take-over` (moves it to backups) |

On Windows, if the MSIX-virtualized copy `%LOCALAPPDATA%\Packages\<Claude PFN>\LocalCache\Roaming\Claude\extensions\<slot id>` exists, every change is refused.

## Transactions

Every change runs as follows:

1. Create the lock exclusively.
2. Stage the new store folder or slot next to its destination, verifying copies by SHA-256.
3. Move the old folders to `backups/<stamp>/` (`store-previous-<id>`, `store-removed-<id>`, `slot-previous`).
4. Rename the staged folders into place.
5. Update REACT_PROFILE.
6. Write `state.json`.

Each step records an undo action. On any error the actions run newest first and the exit code is 1 (3 if the rollback itself failed). Failure injection points for tests are `copy`, `slot-stage`, `slot-swap`, `env` and `state`.

## REACT_PROFILE

- Install, when the variable is absent: set it (Windows: user scope `1`; Linux: write the loader's `environment.d` file) and set `envSetByUs = true`.
- Install, when it is already `1`: leave it as it is. `envSetByUs` stays as before, unless `-AdoptEnv` / `--adopt-env` is given. That flag is used when migrating a tool that set the variable itself: on Linux the loader then writes its own file, so the tool may remove its file afterwards.
- Any other value, or a machine-wide or system-wide definition, blocks every change.
- When no valid extension remains and `envSetByUs` is true: remove the variable if it still equals `1` (Linux: move the loader's file to backups). Then set `envSetByUs = false`.

## Exit codes

0 success · 1 refused, or failed and rolled back · 2 cancelled by the user · 3 rollback failed (manual check; see backups)
